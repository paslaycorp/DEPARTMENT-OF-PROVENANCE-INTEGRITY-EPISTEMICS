# Genesis 2.0 Comparison Ledger

## Function

This ledger records comparative propositions concerning Genesis 2.0 and AEIF using the repository's canonical provenance model.

**Canonical relation:** Claim → Artifact → Version → Date → Evidence → Hash → Location

## Governing rules

1. Similarity is not copying.
2. Correspondence is not derivation.
3. Chronology must be supported by dated evidence.
4. Missing evidence remains missing.
5. Contradictory evidence is retained rather than normalized away.
6. A provenance conclusion must identify the evidence supporting it.
7. Absence of evidence is not evidence of priority, derivation, or copying.

## Interpretation

The ledger deliberately leaves exact Genesis artifact identifiers, hashes, dates, and primary-source locations PENDING until those values are independently captured. This prevents retrospective completion of provenance fields from memory or inference.

## Required promotion path

A PENDING entry may be promoted only when the missing provenance fields are supported by an identifiable artifact and reproducible evidence. A contradiction should be recorded rather than silently replacing the prior record.
