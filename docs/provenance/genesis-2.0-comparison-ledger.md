# Genesis 2.0 Comparison Ledger

## Function

This ledger records comparative propositions concerning Genesis 2.0 and AEIF using the repository's canonical provenance model.

**Canonical relation:** Claim → Artifact → Version → Date → Evidence → Hash → Location

The ledger is deliberately conservative. It records what the evidence supports without converting correspondence into an authorship, copying, derivation, or priority conclusion.

## Governing rules

1. Similarity is not copying.
2. Correspondence is not derivation.
3. Chronology must be supported by dated evidence.
4. Missing evidence remains missing.
5. Contradictory evidence is retained rather than normalized away.
6. A provenance conclusion must identify the evidence supporting it.
7. Absence of evidence is not evidence of priority, derivation, or copying.
8. A model's generated response is evidence of an observed response, not independent proof of the architecture being described.

## Interpretation

The ledger establishes a record of correspondence and evidence requirements. It does not determine who originated a mechanism.

The current record supports meaningful conceptual and functional correspondence, particularly around state transition, coherence/stability, verification, governance, auditability, constrained action, and cross-model behavior. It does not presently establish that the systems are identical, that one derives from the other, or that copying occurred.

## Promotion rules

A **PENDING** entry may be promoted only when the missing provenance fields are supported by an identifiable artifact and reproducible evidence.

A **DOCUMENTED AS AUTHOR CLAIM** entry records that a person publicly made the claim. It does not independently verify the claim.

A contradiction must be recorded rather than silently replacing the prior record.

A hash must never be supplied unless it was calculated from the actual artifact bytes.
